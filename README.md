# 金融舆情负面主体判定：从 TF-IDF、BERT 到 Qwen2.5 QLoRA

基于 [CCF BDCI 2019「金融信息负面及主体判定」](https://www.datafountain.cn/competitions/353) 数据，在**同一套数据划分和官方评估指标**下，系统比较三类方法：

- 传统特征工程：TF-IDF + 逻辑回归
- 判别式微调：BERT / RoBERTa 实体级句对分类
- 大语言模型：Qwen2.5 1.5B / 7B 零样本、少样本提示，以及 7B QLoRA 指令微调

**主要结果**：Qwen2.5-7B QLoRA 在 test 上取得 F1 **0.944**，比 BERT 句对分类（0.926）高 1.8 个百分点；训练只更新了 0.53% 的参数，用单卡 RTX 4080 SUPER 跑了 44 分钟（约 ¥1.2）。代价是推理速度约慢 20 倍。只靠提示词的 7B 模型（0.847）不如 TF-IDF 基线（0.874）。

---

## 1. 任务与评估指标

每条样本是一段金融网络文本（标题 + 正文）和文本中出现的实体列表。需要判断两件事：

1. **文本是否负面**：`negative` 取 0 或 1；
2. **负面信息针对的是哪些实体**：`key_entity`，是实体列表的一个子集。

官方指标：

- **F1_s**：文本级“负面”类的 F1；
- **F1_e**：负面主体的 F1，对所有文本累加实体级的 TP、FP、FN 后再计算；
- **F1 = 0.4 × F1_s + 0.6 × F1_e**。

指标的实现见 [src/metrics.py](src/metrics.py)。

## 2. 数据处理

脚本是 [src/prepare_data.py](src/prepare_data.py)。

| 步骤 | 说明 |
|---|---|
| 清洗 | 删除 URL、HTML 标签、连续的 `??` 乱码、“…全文：”等模板文字；合并标题和正文 |
| 去重 | 删除 21 条完全重复的样本，剩 4978 条 |
| 近重复分组 | 归一化后取前 50 个字作为分组键，393 条近重复文本归为同一组，避免同一新闻的不同转载同时出现在训练集和测试集里造成泄漏 |
| 划分 | 按组、按标签分层，比例 70/15/15，随机种子 42：train 3498 / val 736 / test 744 条文本 |
| 拆成实体对 | 每个（实体, 文本）是一个样本，标签表示该实体是否为负面主体：train 7968 / val 1669 / test 1753 对 |

官方测试集没有公开标签，所以**所有指标都在自己划分出的 test 上计算**。阈值、是否使用后处理规则等选择**只在 val 上决定**，test 只用来报告最终结果。

数据特点：平均每条文本有 2.29 个实体，最多 22 个；7.4% 的实体名不在正文里（例如简称、乱码）；文本长度中位数 145 字，7.4% 超过 512 字。

## 3. 方法

### 3.1 TF-IDF + 逻辑回归（[src/baseline_tfidf.py](src/baseline_tfidf.py)）

- **特征**：截取实体前后各 50 个字作为上下文，并把目标实体替换成占位符“Ｅ”，让模型学的是“Ｅ 涉嫌诈骗”这类模式，而不是记住具体的公司名；对上下文提取字符 1–2gram 的 TF-IDF，再加 5 个结构特征（实体是否在正文中、出现次数、是否被更长的实体包含等）。
- **分类器**：逻辑回归，`class_weight='balanced'`。

### 3.2 BERT / RoBERTa 句对分类（[src/train_bert.py](src/train_bert.py)）

- **输入**：`[CLS] 实体 [SEP] 文本 [SEP]`，文本以实体出现的位置为中心截取，最长 512 token。
- **训练**：全量微调 `bert-base-chinese` 和 `hfl/chinese-roberta-wwm-ext`，学习率 2e-5，batch 32，3 个 epoch，fp16；按 val 上的句对 F1 保留最好的模型。
- **后处理**：任一实体被判为负面，文本就是负面；如果一个短实体名包含在另一个被判为负面的实体名里（如“小资”和“小资钱包”），删掉短的那个。这条规则来自标注习惯：训练集里有 1090 例符合、55 例不符合。是否使用这条规则以及判定阈值，都在 val 上搜索确定。

### 3.3 Qwen2.5 提示词与 QLoRA（[src/llm_data.py](src/llm_data.py)、[src/llm_infer.py](src/llm_infer.py)）

- **文本级生成**：一次输入“指令 + 实体列表 + 文本（截取前 1000 字）”，模型直接输出用分号分隔的负面主体，没有负面主体时输出“无”。指令里写清了负面主体的定义和 4 条规则。
- **少样本**：从 train 里固定选 4 条短文本作为示例（2 条负面、2 条非负面，交替排列），以多轮对话的形式放在问题之前。
- **输出解析**：兼容中文分号、逗号、顿号等分隔符；只保留实体列表里有的名称。另外统计两个比例：**无效输出比例**（无法解析出任何实体）和**幻觉比例**（输出了列表里没有的名称）。
- **QLoRA 微调**：使用 [LLaMA-Factory](https://github.com/hiyouga/LLaMA-Factory)，配置见 [configs/qwen7b_qlora.yaml](configs/qwen7b_qlora.yaml)。
  - 基座模型 Qwen2.5-7B-Instruct 用 4-bit NF4 量化后冻结；所有线性层加 LoRA，r=16，α=32。
  - 可训练参数 4037 万，占总参数的 0.53%。
  - 学习率 1e-4，等效 batch 16，2 个 epoch，cosine 学习率调度。
  - 训练数据与 BERT 使用同一份 train，验证集 loss 两轮分别为 0.066 和 0.064。
  - 推理时把 LoRA 权重合并回 bf16 基座，使用贪心解码。

## 4. 结果（test：744 条文本，1753 个实体对）

| 方法 | F1 | F1_s | F1_e | 无效输出 | 幻觉 | 训练耗时 | 推理 s/千条文本 | 峰值显存 GB | GPU 费用 ¥ |
|---|---|---|---|---|---|---|---|---|---|
| TF-IDF + LR | 0.8738 | 0.9362 | 0.8322 | — | — | 3.6 s | 0.6 | —(CPU) | — |
| BERT 句对分类（全量微调） | 0.9258 | 0.9502 | 0.9096 | — | — | 2.9 min | 4.8 | 7.7 | 0.08 |
| RoBERTa-wwm 句对分类（全量微调） | 0.9258 | 0.9520 | 0.9084 | — | — | 2.8 min | 4.8 | 7.7 | 0.08 |
| Qwen2.5-1.5B 零样本 | 0.6480 | 0.7576 | 0.5750 | 2.0% | 10.6% | — | 42.3 | 4.3 | 0.01 |
| Qwen2.5-1.5B 4-shot | 0.6805 | 0.7576 | 0.6291 | 0.3% | 5.3% | — | 95.7 | 5.9 | 0.03 |
| Qwen2.5-7B 零样本 | 0.8465 | 0.9272 | 0.7927 | 0.5% | 2.4% | — | 93.8 | 17.2 | 0.03 |
| Qwen2.5-7B 4-shot | 0.8099 | 0.9293 | 0.7302 | 0.3% | 1.9% | — | 288.0 | 20.6 | 0.09 |
| **Qwen2.5-7B QLoRA 微调** | **0.9435** | **0.9676** | **0.9275** | 0.1% | 0.5% | 43.8 min | 97.1 | 17.2 | 1.19 |

说明：

- 硬件为单卡 RTX 4080 SUPER 32GB（AutoDL，¥1.58/小时）。
- 句对模型的峰值显存是训练时的数值，大模型是推理时的数值；QLoRA 训练时峰值约 19 GB。
- 句对模型的推理耗时已经从“每千个实体对”换算成“每千条文本”（平均每条文本 2.36 个实体对）。
- 表格由 [src/summarize.py](src/summarize.py) 从 `outputs/results/*.json` 自动生成。
- 每种方法只训练、评估了一次，没有多随机种子重复；test 规模不大，差距在 1–2 个百分点以内时请谨慎解读。

## 5. 误差分析（[src/error_analysis.py](src/error_analysis.py)）

### 5.1 按切片看错误率（逐个实体对，后处理之后）

| 切片 | 对数 | TF-IDF | BERT | QLoRA |
|---|---|---|---|---|
| 全部 | 1753 | 15.2% | 7.9% | **6.4%** |
| 实体名不在正文中 | 123 | 30.9% | 7.3% | 5.7% |
| 文本只有 1 个实体 | 216 | 5.6% | 6.9% | **2.3%** |
| 文本有 ≥4 个实体 | 570 | 17.0% | 8.8% | 9.5% |
| 文本 >500 字（会被截断） | 184 | 18.5% | 7.6% | 7.1% |

- TF-IDF 在“实体名不在正文中”这一切片上的错误率高达 30.9%：它的特征依赖实体附近的上下文，实体不出现在正文里时就没有上下文可用。BERT 读的是整段文本，这一切片的错误率只有 7.3%。
- QLoRA 在“只有 1 个实体”时优势最大；但在“≥4 个实体”的切片上不如 BERT。生成式模型要一次列出整份名单，实体越多越容易漏写或多写，而 BERT 对每个实体单独判断。

### 5.2 BERT 和 QLoRA 的错误构成

| | 错误对数 | 误报 FP | 漏报 FN |
|---|---|---|---|
| BERT | 138 | 83 | 55 |
| QLoRA | 112 | 79 | 33 |
| 两个都错 | 61 | 48 | 13 |
| 只有 BERT 错（QLoRA 修正了） | 77 | 35 | 42 |
| 只有 QLoRA 错（新增的错误） | 51 | 31 | 20 |

QLoRA 的提升**主要来自漏报减少**（55 → 33，对应主体召回率从 0.921 升到 0.956），误报数量基本不变。两个模型有一半以上的错误不重合，说明它们犯错的方式不同，模型融合有提升空间。

### 5.3 BERT 错误的人工归类，以及 QLoRA 是否修正

从 BERT 的 138 个错误中随机抽取 40 个，逐条人工判断原因，样本见 [outputs/error_analysis/bert_errors_sample.csv](outputs/error_analysis/bert_errors_sample.csv)：

| 原因 | 样本数 | QLoRA 修正 |
|---|---|---|
| 主体混淆（负面信息针对的是文中另一个实体） | 9 | 5 |
| 列表式预警帖（一次列出很多平台） | 8 | 2 |
| 标注不一致（同类文本标签相互矛盾） | 7 | 2 |
| 明显负面却漏报 | 3 | 3 |
| 后处理规则误删 | 3 | 3 |
| 隐晦负面，需要金融知识（对赌、触犯红线、控股关系） | 3 | 0 |
| 实体名变体或乱码 | 2 | 2 |
| 否定、转折或疑问语气 | 2 | 1 |
| 关联主体 | 2 | 1 |
| 标注可疑 | 1 | 0 |

- **QLoRA 修正的主要是需要读懂全文的错误**：明显漏报、名称变体、规则误删，以及一半以上的主体混淆。
- **两个模型都处理不好的**：
  - 约 1/5 的错误来自标注噪声（标注不一致、标注可疑），任何模型都学不对；
  - 列表式预警帖和需要金融领域知识的隐晦负面，这是后续改进的方向。

## 6. 结论

1. **微调比提示词重要。** 同一个 7B 模型，零样本 F1 为 0.847，QLoRA 微调后为 0.944。零样本的文本级判断（F1_s 0.927）已经接近 BERT，但主体判定（F1_e 0.793）差距很大。原因在于“负面主体”的标注习惯（例如嵌套名称怎么取、被冒充的平台算不算）很难用几句提示描述清楚，需要从数据中学习。
2. **少样本提示不一定有用。** 对 1.5B 模型，4 条示例主要帮助它规范了输出格式（无效输出从 2.0% 降到 0.3%，幻觉减半）；对 7B 模型反而让主体召回率从 0.81 降到 0.69，推理还慢了 3 倍。
3. **模型规模对提示词方法影响很大。** 1.5B 换成 7B，零样本 F1 提高了约 0.2；1.5B 模型有超过 10% 的输出包含列表外的名称。
4. **BERT 仍然是性价比最高的方案。** 它的 F1 只比 QLoRA 低 1.8 个百分点，训练只要 3 分钟，推理快 20 倍，显存不到一半。如果对精度要求高、又能接受推理成本，可以选 QLoRA；也可以利用两者错误不重合的特点做模型融合。
5. **后处理规则只对句对模型有用。** 大模型已经从指令和训练数据中学到了这条规则，再套一次规则 F1 基本不变（QLoRA 是 0.9435 → 0.9429）。

## 8. 复现

```bash
# 数据处理和传统基线（CPU 即可）
python src/prepare_data.py
python src/baseline_tfidf.py

# BERT / RoBERTa（GPU）
python src/train_bert.py
python src/train_bert.py --model hfl/chinese-roberta-wwm-ext --tag roberta

# 大模型（GPU）：生成训练数据 → 下载模型、安装 LLaMA-Factory → 推理和训练
python src/llm_data.py
bash scripts/llm_setup.sh
bash scripts/llm_run.sh              # 建议逐段复制运行，每一步确认结果

# 汇总和误差分析
python src/error_analysis.py
python src/summarize.py
```

**环境**：

- 数据处理和 TF-IDF：Python 3.13、pandas 3.0、scikit-learn 1.9；
- BERT / RoBERTa：PyTorch 2.8 + transformers 5；
- 大模型：Python 3.12、PyTorch 2.15（CUDA 13.2）、transformers 5.8、peft 0.18、bitsandbytes 0.50、LLaMA-Factory 0.9.6.dev0。

GPU 实验都在 AutoDL 的单卡 RTX 4080 SUPER 32GB 上完成。
